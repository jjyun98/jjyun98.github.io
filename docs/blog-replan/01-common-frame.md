# 01. 공통 글 틀과 작성 규칙

모든 글에 적용한다. 시리즈 파일에 다른 지시가 있으면 시리즈 파일을 따른다.

## 0. 우선 원칙 (2026-11-10, 아래 내용보다 우선)

사용자 검토 결과, 비교 보강과 파일럿의 글이 과하고 **GitHub 버전(`origin/main` `53edf6ec`)의 호흡이 적당하다**고 판단했다.

- **기준은 GitHub 글이다.** GitHub에 없는 실험계획법 시리즈와 미시경제학 강의 예제 반영은 비교 보강 커밋 직전 상태를 기준으로 한다. 글을 다시 쓰지 않고 그 글을 고친다. 절 이름과 순서, 개념에 예시가 바로 붙는 흐름을 유지한다.
- **글의 틀은 방향이지 양식이 아니다.** 개념, 비교, 예시가 글 안에 있으면 된다. `1. 개념 / 2. 비교 / 3. 예시` 번호 구조, `결과의 해석`과 `방법의 선택` 절을 강제하지 않는다.
- **더하는 기준은 하나다.** 오류를 고치거나, 교재의 빠진 내용을 메우거나, 헷갈리는 것을 한 번에 풀어 주는가. 짧게 쓸 수 있으면 짧게 쓴다.
- **분량 상한은 두지 않는다.** 대신 추가한 내용마다 위 기준으로 판단한다. 큰 내용이 빠져 있으면 글을 크게 늘리지 않고 새 글을 검토한다.
- **모의실험은 개념을 보여 줄 때만 쓴다.** 방법의 우열 비교를 위한 반복 실험, 몬테카를로 표준오차 열, 짝지은 차이는 넣지 않는다. 한 번의 결과에는 "이 분할에서는"처럼 범위를 적는다.
- **아래 절과 `02`~`08`의 목표 목차는 참고 자료다.** 범위 대조표와 핵심 식은 빠진 내용을 찾는 데 쓰고, 글의 구조와 분량을 정하는 데 쓰지 않는다. 아래의 몬테카를로 표준오차 규칙과 체크리스트 항목은 적용하지 않는다.

## 1. 목표 수준

**이 블로그만 읽어도 해당 과목을 한 번에 복습할 수 있어야 한다.** 처음 배우는 사람을 위한 긴 도입은 필요 없다. 대신 다음을 만족해야 한다.

| 항목 | 기준 | 판정 방법 |
|---|---|---|
| 범위 | 교재의 모든 절이 글에 있거나, "다루지 않음"이라고 명시되어 있다 | 시리즈 파일의 대조표에 빈칸이 없다 |
| 개념 | 정의, 식, 가정을 교재를 다시 펴지 않고 확인할 수 있다 | 핵심 식 목록이 글에 모두 있다 |
| 비교 | 헷갈리는 개념 쌍의 차이를 표 하나로 찾을 수 있다 | 글마다 비교 절이 한 번만 나온다 |
| 사용 | 각 방법을 언제, 어떻게 쓰고 결과를 어떻게 읽는지 알 수 있다 | 방법마다 실행한 예시가 있다 |

## 2. 글의 틀

세 부분을 **개념 → 비교 → 예시와 사용** 순서로 쓴다. 글의 성격에 따라 두 유형 중 하나를 쓰며, 글별 유형은 시리즈 파일에 지정되어 있다.

### A형: 방법 묶음형

같은 문제를 푸는 여러 방법을 다루는 글이다(분류기 비교, 평활법 비교 등). 먼저 개념을 모두 세운 뒤 비교하고, 같은 자료로 실행한다.

```markdown
도입 2~4문장: 어떤 문제를 푸는가, 교재 범위, 앞 글과의 연결

## 1. 개념
### 1.1 방법 A      정의 → 식 → 추정·유도의 핵심 단계 → 가정 → 직관(그림) → 주의
### 1.2 방법 B
### 1.3 방법 C

## 2. 비교
관계를 보여주는 식(예: A는 B의 특수한 경우) → 비교표 1개 → 차이가 드러나는 그림·모의실험 → 선택 기준

## 3. 예시와 사용
### 3.1 자료와 준비
### 3.2 방법 A      코드 → 실제 출력 → 해석 → 언제 쓰는가
### 3.3 방법 B
### 3.4 같은 자료에서의 비교

## 정리      핵심 식과 혼동 포인트 3~6줄 (비교표를 반복하지 않는다)
## 참고자료
```

### B형: 단계 흐름형

앞 개념이 다음 개념의 재료가 되는 글이다(정의 → 정리 → 다음 정리, 소비자 선택 → 수요). 소주제마다 개념과 예시를 붙이고, 비교는 소주제 안 또는 글 끝에 둔다.

```markdown
도입 2~4문장

## 1. 소주제 1
개념(글 + 식) → 바로 이어지는 예시·계산 → 사용처

## 2. 소주제 2
개념(글 + 식) → 예시·계산 → 사용처

## n. 비교      이 글에서 헷갈리는 개념 쌍을 표 하나로
## 정리
## 참고자료
```

### 개념 한 단위의 구성

아래 순서를 기본으로 한다. 해당 없는 항목은 뺀다.

1. **한 문장 정의**: "X는 ~하는 ~이다."
2. **식**: 모형식 또는 목적함수. 기호는 식 바로 아래에서 설명한다.
3. **유도**: 시험과 복습에 필요한 핵심 단계만 쓴다. 긴 대수 전개는 줄이되 결과는 생략하지 않는다.
4. **가정·조건**: 언제 성립하는가.
5. **직관**: 식이 무엇을 뜻하는지 글로 설명하고, 필요하면 그림을 넣는다.
6. **주의**: 흔한 오개념. `> **주의**` 인용 블록으로 쓴다.

### 비교 절의 구성

- 글 하나에 **`## 비교`는 한 번만** 둔다. 같은 내용의 표를 해석, 선택, 정리 절에서 반복하지 않는다.
- 먼저 관계를 식으로 쓴다. 그다음 표로 정리한다.
- 표의 열은 시리즈 파일의 "비교 축"을 따른다.
- 선택 기준은 별도 절로 빼지 않고 비교 절 끝에 표 또는 짧은 목록으로 둔다.

### 예시와 사용의 구성

- 예시마다 **코드 → 출력 → 해석** 순서를 지킨다. 해석에는 출력의 숫자를 인용한다.
- 코드가 없는 과목(미시경제학)은 **문제 → 풀이 → 결과의 경제적 의미**로 쓴다.
- 손계산이 있는 강의 예제는 유지한다. 코드 결과와 맞으면 일치한다고 적는다.
- "언제 쓰는가"를 1~3문장으로 적는다.

### 기존 글을 고칠 때의 대응

| 기존 절 | 처리 |
|---|---|
| 개요 | 도입 문단으로 줄인다. 표가 있으면 비교 절로 옮긴다 |
| 방법 간 비교 + 방법의 선택 | `## 비교` 하나로 합친다 |
| 자료를 이용한 비교 | `## 예시와 사용`으로 옮긴다 |
| 결과의 해석 | 해당 예시의 해석으로 나눠 넣고 절은 없앤다 |
| 정리·요약 | 핵심 식과 혼동 포인트만 남긴다 |
| 자주 하는 실수 | 해당 개념의 `주의`로 옮기거나, R4DS에 한해 절을 유지한다 |

## 3. 내용 규칙

### 정확성

시리즈 파일의 "핵심 식"은 넣을 내용을 정한 것이다. 기호와 형태는 교재와 기존 글의 표기를 따르고, 옮기기 전에 교재와 대조한다.

1. **숫자는 실행 결과에서만 가져온다.** 출력, 계수, 오차를 추정하거나 지어내지 않는다.
2. 실행할 수 없는 코드는 `norun`으로 표시하고 출력 숫자를 쓰지 않는다. 교재의 수치를 인용할 때는 "ISLR 표 10.2"처럼 출처를 적는다.
3. 교재와 강의의 내용이 다르면 둘 다 적고 어느 쪽 기준인지 밝힌다.
4. 글을 고친 뒤 산문에 적힌 숫자를 실행 로그와 대조한다.

### 모의실험 해석

- 반복 실험 결과에는 **몬테카를로 표준오차**를 함께 적는다: 평균이면 `sd/sqrt(B)`, 비율이면 `sqrt(p(1-p)/B)`.
- 차이가 표준오차의 2배보다 작으면 "차이가 있다"고 쓰지 않는다.
- 한 번의 분할, 하나의 시드로 얻은 결과에서 방법의 우열을 일반화하지 않는다. "이 자료, 이 분할에서는"이라고 범위를 적는다.
- 인과 표현은 설계가 뒷받침할 때만 쓴다.

### 설명 순서

- 아직 나오지 않은 개념을 설명 없이 쓰지 않는다. 불가피하면 한 줄로 설명하고 링크를 건다.
- 코드를 예고한 문장("다음과 같다") 바로 다음에 코드를 둔다.
- 같은 표, 같은 그림을 한 글에서 두 번 쓰지 않는다.
- 수치 예제가 먼 뒤의 글에 속하면 그 글로 옮긴다.

### 문체와 흔적

- 이다체로 쓴다. 군더더기 수식어, 과장, 번역투를 쓰지 않는다.
- 글과 무관한 작업 흔적을 지운다: "원본 강의자료", "원본 슬라이드", "원본 예제", "원본 자료" 같은 표현.
- 새 소프트웨어 버전에 따라 달라지는 기본값은 패키지 함수와 인자를 명시한다. 예: `ndiffs(test = "kpss")`.

### 그림

| 종류 | 위치 | 언제 |
|---|---|---|
| 개념도 (Excalidraw 손그림 스타일 SVG) | `./figures/` | 구조, 절차, 기하, 관계 설명 |
| R 결과 이미지 (PNG) | `./images/` | 실행 결과 |
| 경제학 곡선, 게임나무 등 | `./figures/` SVG | 미시경제학의 그래프 |

- 모든 이미지에 내용을 설명하는 alt를 쓴다.
- 그림은 글을 되풀이하지 않고, 글로 설명하기 어려운 것을 보여준다.
- 기존 SVG 스타일을 따른다. 작업 전 같은 시리즈의 기존 SVG 하나를 읽어 형식을 맞춘다.
- 표는 6열 이하를 권장한다. 열이 더 필요하면 표를 나눈다.

### 링크

- 다른 글의 개념을 쓰면 `/posts/<slug>`로 링크를 건다.
- 글 끝의 이전·다음 글은 사이트의 시리즈 내비게이션에 맡긴다. 본문의 "다음 글" 문장은 `seriesOrder`를 바꾼 글에서 다시 확인한다.
- 시리즈 간 공통 주제의 담당 글은 `00-README.md`의 "시리즈 간 연결" 표를 따른다.

## 4. Frontmatter

```yaml
---
title: '시리즈명 - 글 제목'
published: 2022-03-09      # 기존 값을 유지한다
draft: false
description: '이 글의 범위를 한 문장으로'
series: '시리즈명'
seriesOrder: 3             # WP-0에서 추가되는 필드. 시리즈 안 순서
tags: ['...']
---
```

신규 글은 `draft: true`로 시작해 완성 후 `false`로 바꾼다. **기존 slug는 바꾸지 않는다.** URL이 유지되어야 한다.

## 5. 실행 환경

모든 명령은 저장소 루트에서 실행한다.

| 작업 | 명령·경로 |
|---|---|
| 글의 R 코드 실행, 이미지 저장 | `Rscript _tmp/r4ds/run_md.R src/content/posts/<시리즈>/<slug>/index.md` |
| 실행 로그 | `_tmp/r4ds/logs/<slug>.log` |
| 개발 서버 | `npm run dev` (포트 4321, `/posts/<slug>`, `/series/<이름>`) |
| 빌드 확인 | `npm run build` |

**코드 블록 표시 규칙(`run_md.R`):**

- `` ```r ``: 글 안에서 위에서부터 같은 환경으로 실행한다.
- 블록 바로 아래 줄이 `![...](./images/파일.png)`이면 그 블록의 마지막 ggplot을 그 경로에 저장한다.
- `` ```r norun ``: 실행하지 않는다.
- `` ```r base ``: base 그래픽을 저장한다.
- `` ```r w=10 h=3.5 ``: 저장 크기를 인치로 지정한다.

## 6. 글 완료 체크리스트

글 하나를 마칠 때 모두 확인한다.

- [ ] 시리즈 파일의 "범위" 항목이 모두 들어 있다
- [ ] 시리즈 파일의 "핵심 식"이 모두 있다
- [ ] 비교 절이 한 번만 있고, 같은 표가 반복되지 않는다

- [ ] `run_md.R`이 에러 없이 끝났고 로그를 확인했다 (코드가 있는 글)
- [ ] 산문의 숫자가 로그와 일치한다
- [ ] 모의실험에 몬테카를로 표준오차가 있다
- [ ] 이미지 경로가 모두 존재하고 alt가 있다
- [ ] `npm run build`가 통과한다

## 7. 작업 규칙

- 글 작업 전 그 글 전체를 읽는다. 이 계획의 줄 번호는 커밋 `3d034d2f` 기준이므로 이후 달라질 수 있다.
- 계획과 실제 글이 다르면 실제 글을 확인해 판단하고, 차이를 `00-README.md`의 "계획과 달라진 점"에 적는다.
- 기존 글의 잘 된 설명은 지우지 않는다. 시리즈 파일의 "유지" 항목은 틀을 바꿔도 내용을 살린다.
- 사용자가 요청할 때만 커밋하고 푸시한다.
- 글을 쓸 때 코드를 먼저 넣고 `run_md.R`로 실행한 뒤, 로그의 숫자를 본문에 옮긴다. 본문에 자리표시자(`TBD`)를 두었다면 끝나기 전에 `grep -n TBD`로 남은 것이 없는지 확인한다.
- Python이나 셸 스크립트로 글을 고칠 때 LaTeX가 깨지기 쉽다. 일반 Python 문자열에서는 `\times`의 `\t`가 탭으로, `\approx`의 `\a`가 제어 문자로 바뀐다. 셸 heredoc은 따옴표 없이 쓰면 백틱 안의 내용이 명령으로 실행된다. LaTeX와 백틱이 들어가는 수정은 Edit 도구로 하고, 스크립트를 쓴다면 raw 문자열(`r'''...'''`)과 따옴표 친 heredoc(`<<'E'`)을 쓴다. 수정 후 제어 문자가 없는지 확인한다.
- `summarise()` 안에서 `across()`로 열을 평균으로 덮어쓰면, 같은 `summarise()`의 뒤쪽 식이 덮어쓴 값을 참조한다(`sd()`가 `NA`). 파생 열은 먼저 `mutate()`로 만든다.
